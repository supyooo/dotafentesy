## Стек
| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript везде (backend + общие типы с фронтом) | ошибки ловит компилятор, а не ревью; один контракт для API и фронта |
| API | NestJS на Fastify | модули по доменам = границы, понятные аналитику |
| База | PostgreSQL 17 + Drizzle ORM | пересчёты таблиц — set-based SQL; схема — `09-database.md` |
| Очереди | BullMQ (Redis) | сбор с API, пересчёты, дедлайны, повторы |
| Redis | очереди, кэш, pub/sub, live-таблицы (sorted sets) | |
| Live для клиента | SSE, не WebSocket | поток только сервер → клиент; действия — обычный HTTP |
| Контракт | zod → OpenAPI | валидация, документация, B2B |
| Наблюдаемость | Sentry + Prometheus/Grafana | |

Рассмотрены и отложены: Rails (+AnyCable) — динамическая типизация хуже при работе «аналитик + агент»; Go — хорош для live, но многословен на бизнес-правилах, можно взять точечно для сборщика позже; Elixir — малая экосистема.

## Схема live
```
Steam GetLiveLeagueGames ── опрос 5–10 с ──► live-сборщик ──► дельты очков игроков (≤10 на карту)
                                                   │
                                   Redis pub/sub, канал турнира
                                   ┌───────────────┴─────────────────┐
                    SSE всем подписчикам турнира          раз в 30–60 с: предварительные таблицы
                    одно сообщение на всех                 и группы (Redis), итог — Postgres
                    клиент сам считает свой состав (знает 5 игроков и капитана)
```
Не считать персональные суммы на каждом тике: одно широковещательное сообщение вместо N персональных.

## Три уровня данных
| Момент | Источник | Поля | Очки |
|---|---|---|---|
| Во время карты (с задержкой трансляции, `stream_delay_s`) | Steam live | герой, драфт, K/D/A, добивания, денаи, net worth, GPM/XPM, уровень, предметы, счёт серии, вышки, Рошан | убийства, смерти, помощь, добивания |
| Конец карты (~1–2 мин) | Steam / OpenDota, детали матча | победа, урон по героям и строениям, лечение | победа, урон по строениям |
| После разбора реплея (5–15 мин) | OpenDota (резерв STRATZ) | варды, снятые варды, оглушения, стаки | варды, оглушения, стаки |

Каждая цифра несёт `data_tier` = live | basic | parsed. UI показывает статус («live · без вардов и оглушений»), событие «разбор реплея готов» — отдельное уведомление.
Расхождение итога с live показывать явной строкой «корректировка», не менять число молча. Места во время карты — «предварительно».

## Источники
| Что | Источник | Условия |
|---|---|---|
| Расписание, сетки, составы | Liquipedia MediaWiki API | 1 запрос / 2 с, `action=parse` 1 / 30 с, свой User-Agent с контактом, gzip, CC-BY-SA — подпись «данные: Liquipedia» на сайте. LiquipediaDB API: бесплатно только некоммерческим (60 запросов/час), коммерческий Basic $49/мес за тип данных — подключить с первым B2B |
| Live | Steam Web API `GetLiveLeagueGames` | ключ Steam; проверить работоспособность в первую очередь |
| Итог карты | OpenDota (без ключа), резерв STRATZ (токен, ~2000 запросов/час на бесплатном — перепроверить) | |
| Официальные данные | GRID (официальный поставщик BLAST, ESL, DreamLeague, TI; <200 мс, варды и Рошан в live) | платно; подать заявку на Open Access; полный доступ — через B2B-партнёра (BLAST) |
| Не использовать | DLTV, Hawk.live, Cyberscore | публичного API нет, парсинг — нарушение условий; Hawk — кандидат в партнёры (виджет), DLTV/Hawk — эталон задержки |
| Позже | PandaScore | бесплатно — календарь (1000 запросов/час); статистика от €400/мес |

Все адаптеры пишут в одну нормализованную схему, сырые ответы — в `raw_payloads`, внешние ID — в `external_refs`.

## Хостинг — НЕ РЕШЁН
Ждём ответа Georgy про аудиторию. Факторы:
- Российские провайдеры замедляют Cloudflare (с июня 2025 обрыв после ~16 КБ). Прототип на Pages весит 220 КБ — проверить открытие без VPN.
- 152-ФЗ: ПДн граждан РФ первично хранятся в РФ → для российской аудитории база пользователей в РФ (Yandex Cloud / Selectel / Timeweb + российский CDN).
- Международная аудитория / B2B с организаторами — Hetzner / Fly.io + Cloudflare; оплата из РФ — отдельная проблема.
